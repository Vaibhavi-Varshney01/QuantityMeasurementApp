# QuantityMeasurementApp

This solution implements the standard Quantity Measurement kata and extends it with persistence, caching, console/REST UIs, and JWT-protected authentication.

## Getting started
- Build everything via `dotnet build QuantityMeasurementApp.sln` (the multi-project solution is wired in `QuantityMeasurementApp.sln`, which orchestrates all the layers).
- Run the interactive console with `dotnet run --project QuantityMeasurementConsoleApp/QuantityMeasurementConsoleApp.csproj`, choose the repository implementation (cache or Redis + SQL Server) from `QuantityMeasurementConsoleApp/Program.cs:17-83`, and the menu at `QuantityMeasurementConsoleApp/Menu/Menu.cs:17-220` exposes the first 15 use cases.
- Run the Web API with `dotnet run --project QuantityMeasurementWebAPI/QuantityMeasurementWebAPI.csproj`; `QuantityMeasurementWebAPI/Program.cs:17-106` wires EF Core, optional Redis caching, Swagger, health checks, and JWT authentication before mounting the controllers.

## Architecture snapshot
- **Model layer** (`QuantityMeasurementModel/*`) encapsulates units, DTOs, entities, and a custom exception used by temperature arithmetic.
- **Repository layer** holds in-memory caching (`QuantityMeasurementRepository/Cache/QuantityMeasurementCacheRepository.cs:5-44`), Redis + SQL combination (`QuantityMeasurementRepository/Cache/QuantityMeasurementRedisCacheRepository.cs:7-161`), and the primary SQL implementation (`QuantityMeasurementRepository/Database/QuantityMeasurementDatabaseRepository.cs:1-220`), all accessed through `IQuantityMeasurementRepository` and tested by `QuantityMeasurementTests/DatabaseRepositoryTest.cs:12-181`.
- **Service layer** (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:9-214`) centralizes conversions, arithmetic, validation, and category checks. The N-tier business layer (`QuantityMeasurementBusinessLayer/Service/QuantityMeasurementServiceImpl.cs:17-186`) wraps it, logs each operation via `IQuantityMeasurementRepository`, and exposes history/counter helpers. Web API controllers (`QuantityMeasurementWebAPI/Controller/QuantityMeasurementController.cs:13-70`) and auth controller (`QuantityMeasurementWebAPI/Controller/AuthController.cs:7-32`) call into this layer, with JWT helpers (`QuantityMeasurementBusinessLayer/Helper/JWTHelper.cs:10-55`) and auth implementation (`QuantityMeasurementBusinessLayer/Service/AuthServiceImplementation.cs:22-86`).

## Use cases (UC1–UC18)
1. **UC1 – Feet equality** checks two `Feet` instances against nulls and uses their `Equals` override; this is what `QuantityMeasurementTests/UnitTest1.cs:18-37` exercises and what `QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:17-31` provides.
2. **UC2 – Inches equality** mirrors the feet flow via `QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:25-31` and the twin tests `QuantityMeasurementTests/UnitTest1.cs:43-66`.
3. **UC2 extended – Feet vs Inch cross-check** demonstrates the canonical conversion (1 foot = 12 inches) by calling the generic `AreEqual` helper (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:9-15`) and is validated at `QuantityMeasurementTests/UnitTest1.cs:68-85`.
4. **UC3 – Generic length equality** lets any `Quantity<LengthUnit>` pair be compared after converting to the base unit (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:173-214`); the `UnitTest1` class covers same-unit, cross-unit, and null cases near `QuantityMeasurementTests/UnitTest1.cs:87-118`.
5. **UC4 – Length conversions** rely on `QuantityMeasurementService.Convert` (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:54-63`) plus the helper extensions in `QuantityMeasurementRepository/Service/Extensions.cs:1-75` to turn feet, yards, inches, and centimeters into each other with validations; dozens of edge-case tests live in `QuantityMeasurementTests/UnittoUnitTest.cs:21-63`.
6. **UC5 – Conversion robustness** includes precision checks, round trips, zero/negative handling, and invalid inputs (`QuantityMeasurementTests/UnittoUnitTest.cs:33-63`), ensuring `Convert` rejects NaN and undefined units.
7. **UC6 – Adding lengths (default target)** uses `QuantityMeasurementService.Add(Quantity<LengthUnit>, …)` (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:33-138`) and is covered by `QuantityMeasurementTests/UnitAdditionTest.cs:21-123`, which verifies same-unit, cross-unit, commutativity, zero/negative values, and null operands.
8. **UC7 – Adding lengths with explicit target unit** lets callers specify the result unit, rounding appropriately (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:118-161`); `QuantityMeasurementTests/TargetAdditionTest.cs:18-160` asserts target-specific conversions, large values, and tolerance bands.
9. **UC8 – Subtract lengths (default)** and **UC9 – subtraction with target unit** use `QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:140-161` and are exercised by `QuantityMeasurementTests/SubractDivisionTest.cs:23-160`, which covers same-unit, cross-unit, volume, zero, negative, non-commutativity, and validation failures.
10. **UC10 – Divide lengths** lives in `QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:163-170` and is tested by `QuantityMeasurementTests/SubractDivisionTest.cs:167-253`, which asserts ratios, division-by-zero handling, and category guards.
11. **UC11 – Weight comparison** reuses `GenericAreEqual<WeightUnit>` (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:173-214`) and `QuantityMeasurementTests/QuantityMeasurementServiceTest.cs:328-359` plus the domain tests in `QuantityMeasurementTests/WeightMeasurementTest.cs:50-259`.
12. **UC12 – Weight conversion** is covered via the shared `Convert` method and `Quantity<WeightUnit>.ConvertTo`, with tests such as `QuantityMeasurementTests/QuantityMeasurementServiceTest.cs:300-323` and `QuantityMeasurementTests/WeightMeasurementTest.cs:35-205` ensuring precise Gram/Kilogram/Pound/Tonne translations.
13. **UC13 – Weight addition/subtraction** draws on the generic helpers (`QuantityMeasurementRepository/Service/QuantityMeasurementService.cs:117-161`) and `QuantityMeasurementTests/QuantityMeasurementServiceTest.cs:365-429` to confirm sum/difference results plus cross-unit handling and exception paths.
14. **UC14 – Weight division** uses the same helper and `QuantityMeasurementTests/QuantityMeasurementServiceTest.cs:436-459` to confirm ratios and division-by-zero behavior.
15. **UC15 – Temperature comparison** relies on the temperature-aware units (`QuantityMeasurementModel/Models/TemperatureUnit.cs`) and is validated exhaustively by `QuantityMeasurementTests/TemperatureMeasurementTest.cs:13-195`.
16. **UC16 – Temperature conversion** leans on `Quantity<TemperatureUnit>.ConvertTo` and the `Convert` helper; checks such as `QuantityMeasurementTests/TemperatureMeasurementTest.cs:95-195` show 0°C vs 32°F, 100°C vs 212°F, and round-trip symmetry.
17. **UC17 – Unsupported temperature arithmetic** is enforced by throwing `QuantityMeasurementException` for `Add`, `Subtract`, and `Divide`, as `QuantityMeasurementTests/TemperatureMeasurementTest.cs:198-221` asserts.
18. **UC18 – Measurement command center** writes every operation to the chosen repository through the menu (`QuantityMeasurementConsoleApp/Menu/Menu.cs:17-220`), whether it is the in-memory cache (`QuantityMeasurementRepository/Cache/QuantityMeasurementCacheRepository.cs:5-44`), the Redis-backed cache (`QuantityMeasurementRepository/Cache/QuantityMeasurementRedisCacheRepository.cs:7-161`), or the SQL store (`QuantityMeasurementRepository/Database/QuantityMeasurementDatabaseRepository.cs:1-220`), with persistence verified by `QuantityMeasurementTests/DatabaseRepositoryTest.cs:12-181` and integration tests such as `QuantityMeasurementTests/IntegrationTest.cs:151-226`.

## Persistence, history, and APIs
- Every console or API operation uses `QuantityMeasurementBusinessLayer/Service/QuantityMeasurementServiceImpl.cs:17-186` to persist a `QuantityMeasurementEntity`, expose history/count helpers, and flag errors.
- Swagger-enabled REST endpoints (`QuantityMeasurementWebAPI/Controller/QuantityMeasurementController.cs:13-70`) require JWT (`QuantityMeasurementWebAPI/Program.cs:47-106`) and serve comparison, arithmetic, conversion, and history queries.
- Authentication flows (`QuantityMeasurementWebAPI/Controller/AuthController.cs:7-32`, `QuantityMeasurementBusinessLayer/Service/AuthServiceImplementation.cs:22-86`) hash passwords with `QuantityMeasurementBusinessLayer/Helper/PasswordHelper.cs` and issue JWTs from `QuantityMeasurementBusinessLayer/Helper/JWTHelper.cs:10-55` so API clients can securely call the protected endpoints.
